# 「造一个 Agent」Python 语法闯关游戏 — 设计文档

日期：2026-09-05
状态：已获用户确认

## 背景与目标

用户是 Java 开发者，正在学习 Python 语法，目标是做 agent 开发。直接学语法太枯燥，需要一个游戏化的学习工具。核心要求（用户原话提炼）：

1. **不枯燥** — 通关式玩法，有剧情、有进度感
2. **便于理解** — 每个语法点配 Java 对照，复用已有的 Java 肌肉记忆
3. **知道用在哪里** — 每个语法点都绑定一个真实的 agent 开发场景

## 玩法设计

主线剧情：玩家从零造一个 agent，共 13 关。每关固定四步：

1. **剧情卡**：agent 遇到一个需求（例："它现在记不住你说过的话"）
2. **知识卡**：需要哪个 Python 语法 + Java 对照（f-string vs `String.format`、`self` 显式传递、duck typing vs 接口等）
3. **任务**：在网页代码编辑器里补全/改写代码，点运行
4. **过关**：判题通过，对应"零件"（记忆模块、工具模块……）可视化装配到 agent 身上，进度推进

## 关卡主线（13 关）

| 关 | 语法点 | Agent 场景 |
|---|---|---|
| 1 | 变量、字符串、f-string | 拼出第一个 system prompt |
| 2 | list | 存对话历史消息 |
| 3 | dict | 消息结构 `{"role": "user", "content": ...}` |
| 4 | if/elif | 用户意图路由 |
| 5 | for/while、推导式 | agent loop 雏形（think→act 循环） |
| 6 | 函数、默认参数、解包 | 封装 LLM 调用 |
| 7 | 异常处理 | 工具调用失败重试 |
| 8 | 文件读写、json | 持久化记忆到磁盘 |
| 9 | class | 定义 Tool / Agent 类（重点 Java 对比） |
| 10 | 装饰器 | `@tool` 注册工具（LangChain 同款写法） |
| 11 | 模块与包 | 把单文件拆成 agent 项目结构 |
| 12 | async/await | 并发调多个工具（对比 Java 线程模型） |
| 13 | 终关 | 组装完整最小 agent 并跑起来 |

终关使用 **mock LLM**（假回复），无需 API key 即可跑通；代码中预留真实 API 的接口位置，接真模型时改一处即可。

## 技术方案

### 架构

```
浏览器（单页面前端）  ──HTTP──>  本地 FastAPI 判题服务
                                    │
                                    └─> subprocess 隔离运行用户代码（5 秒超时）
                                          └─> 运行结果 + 判题断言
```

### 后端

- 本地 FastAPI 服务：接收代码 → subprocess 隔离运行（5 秒超时）→ 返回 stdout/stderr + 判题结论
- 选 FastAPI 的理由：真实 Python 环境、真实报错（报错本身也是学习材料）；FastAPI 也是 agent 开发常用技术，顺手熟悉
- 判题：每关一个判题器，运行玩家代码后做断言（例："记忆文件真的写进 json 了吗"），失败时给**人话提示**，不甩原始 traceback

### 前端

- 单个 HTML 页面，无构建步骤
- 组成：代码编辑区 + 剧情/知识卡 + 运行按钮 + agent 装配进度可视化
- 不引入 React 等框架，保持项目简单可维护
- 进度存浏览器 localStorage

## 范围外（YAGNI）

- 不做账号系统、不做云端保存
- 不做排行榜、成就系统
- 不接入真实 LLM API（只留接口）

## 测试

- 每关的判题器用 pytest 测：错误答案必须判失败、正确答案必须判通过
- 前端用 Playwright 做一次端到端冒烟：打开页面 → 跑第 1 关 → 看到过关提示
